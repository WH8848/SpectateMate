# 「右键队友头像 → 直接看到他的战斗画面」可行性与风险评估

> 评估对象：《杀戮尖塔 2》v0.111.0（commit 41cef1ea）· Godot 4.5.1 mono · net9.0
> 依据来源：反编译工程 `E:\MOD\sts2\sts2\0.111.1\src`（3545 个 .cs）、工坊 mod `TeammateSpectate v1.2.0` 反编译、本机实测日志

---

## 0. 摘要

**结论先说：这个需求有 60% 是伪命题，剩下 40% 有成熟的低成本解法。**

| 判断 | 内容 |
|---|---|
| 不可行 | 离屏渲染复制画面（路径 D）—— Godot 节点树物理限制 |
| 不划算 | 自绘仿原版覆盖整页（路径 C）—— 1500+ 行，永远「像」不是「是」 |
| 不划算 | 视频流传输（路径 E）—— 要做真直播，不如直接用 Steam 直播 |
| 高风险 | 原生 UI 接管（路径 A）—— 效果最好，但会威胁你自己的手牌 |
| **推荐** | 原版全屏界面拼装（路径 F）+ 只读覆盖层（路径 B）—— 零复刻、真原生、风险极低 |

## 1. 必须先澄清的物理前提

### 1.1 他没有一个「独立的画面」

这个游戏是**纯 2D + 确定性锁步**架构，没有「视角」这个概念：

| 事实 | 源码依据 |
|---|---|
| 战斗房间是 `Control`，不是 3D 场景 | `Core\Nodes\Rooms\NCombatRoom.cs:30` —— `public partial class NCombatRoom : Control` |
| 全工程没有 `Camera2D`，只有一处注释提到 camera 缩放 | `Core\Nodes\Rooms\NCombatRoom.cs:365` |
| 队友的角色**已经在你的屏幕上渲染** | `Core\Nodes\Combat\NCreature.cs:164` —— `_isRemotePlayerOrPet`；远程玩家有独立 creature 节点 |
| 所有玩家共享同一个 `CombatState` | `Core\Combat\CombatState.cs:81` —— `Players` 包含全部玩家 |
| 手牌/能量在本地就能读到 | `CombatManager.cs:454-461` 对全员调 `PopulateCombatState` |

**换句话说：地形、敌人、Boss、他的角色模型、他的血条、他身上的 buff —— 这些你本来就看得见。**

所谓「他的战斗画面」，在几何上和你的是同一个画面。

### 1.2 真正缺的只有三样东西

1. **他的手牌**（`PlayerCombatState.Hand` —— 本地有数据，但绑定在他的 UI 上，你的屏幕不显示）
2. **他的能量 / 星 / 遗物 / 药水**（同上）
3. **他此刻的界面**（地图选路、奖励结算、选牌）—— 只有 `NetScreenType` 枚举，没有内容

### 1.3 一个反直觉的结论

> 你要的「像看直播一样」，其实 90% 的视觉元素**已经在你屏幕上**。
> 覆盖整页不会让你「看到更多」，只会让你「看不到自己」。

所以真正要解决的问题不是「如何看见他的画面」，而是 **「如何把他的 UI 数据补到我的画面上」**。
这个问题决定了下面所有路径的性质。

## 2. 六条实现路径

### 路径 A：原生 UI 接管（工坊 TeammateSpectate 的做法）

**原理**：不复制、不重绘，而是「让原生 UI 以为自己正在显示另一个玩家」。

四个层次：

```
① displayed player override
   NTopBar / NRelicInventory / NPotionContainer / NCombatUi /
   NCombatPilesContainer / NEnergyCounter / NStarCounter
   → Prefix 压栈「当前显示玩家 = 队友」，Finalizer 弹栈

② 手牌栏换血（最危险）
   RemoveLocalHandCards  → 把自己的 NHandCardHolder 摘下塞进隐藏 Control
   AddSpectateHandCards  → NCard.Create(队友卡) + hand.Add()
   RestoreLocalHandCards → 把自己暂存的 holder 放回去

③ 拦交互
   patch NPlayerHand.OnHolderPressed / StartCardPlay /
         UpdateHandDisabledState / AnimDisable

④ 视觉附属
   复现瞄准箭头、目标 reticle、屏幕边框、「观战中」标签
```

| 维度 | 评估 |
|---|---|
| 效果 | ★★★★★ 视觉上与「在玩他的角色」无异 |
| 工作量 | 1500–1800 行（C 段和 D 段必须一起做） |
| 风险 | ★★★★☆ 见 §4 |
| 致命点 | `_parkedLocalHolders` 是内存暂存；任何一步异常 → 你自己的手牌丢失，本局报废 |

**评价**：这是唯一能真正达到「像在玩他」的方案，但它同时是唯一会**伤害使用者本人**的方案。

---

### 路径 B：只读覆盖层（当前已实现）

**原理**：读本地状态 → 在自己的 `CanvasLayer` 里画自己的节点。

- 数据源：`Player.PlayerCombatState`、`RunManager.Instance.InputSynchronizer`
- 渲染：`NCard.Create()` 生成卡面副本（不是搬 holder）
- 不碰任何原生节点的所有权

| 维度 | 评估 |
|---|---|
| 效果 | ★★★☆☆ 信息全，但不像「他的界面」 |
| 工作量 | 200–300 行（已完成） |
| 风险 | ★☆☆☆☆ 最坏情况是小窗不显示 |

---

### 路径 C：全屏自绘仿原版

**原理**：照抄战斗界面布局，画一个全屏覆盖层。

需要复刻的清单：

```
顶部   HP 条 / 金币 / 4 个药水槽 / 能量球 / 星 / 遗物栏 / 牌库按钮 / 设置按钮
中部   玩家角色 + 血条 + buff 图标 + 格挡盾 / 敌人 + 意图箭头 + 伤害数字
底部   手牌扇形布局 / 能量 / 结束回合按钮 / 抽牌堆 / 弃牌堆
杂项   九宫格边框 / 字体 / 发光 / tween 动画 / 卡面 hover 放大
```

| 维度 | 评估 |
|---|---|
| 效果 | ★★☆☆☆ 永远「像」而不是「是」，字体/间距/动效对不上 |
| 工作量 | 1500–2500 行，且游戏每次改 UI 都要跟 |
| 风险 | ★★☆☆☆ 不伤游戏，但维护成本高 |
| 收益 | **负** —— 全屏盖住后你自己的手牌和结束回合按钮都看不见了 |

**评价**：投入产出比最差的一条路。你在重写游戏的视觉层，而不是在实现观战。

---

### 路径 D：离屏渲染复制画面（SubViewport）

**原理设想**：把 `NCombatRoom` 再渲染一份到旁边。

**结论：Godot 的节点树模型下不可行。**

| 障碍 | 说明 |
|---|---|
| 单父级 | 一个 `Node` 只能有一个父节点，无法同时挂在两个 `Viewport` 下 |
| `ViewportTexture` 只能引用别的 Viewport | 不能把当前 Viewport 的内容「复制」一份出来 |
| 无相机 | 2D `Control` 层没有可切换的相机，不存在「他的视角」 |
| 克隆成本 | 想复制画面只能深拷贝整棵节点树（含所有状态），等于再跑一个游戏 |

> 工程里 `SubViewport` 的唯一用途是 VFX（`NMonsterDeathVfx.cs:117`、`NDoomVfx.cs:85`、`NPotionFlashVfx.cs:33`），与画面复制无关。

---

### 路径 E：视频流传输（真·直播）

**原理**：`GetViewport().GetTexture().GetImage()` 截帧 → 压缩 → 通过自定义网络消息发给对方 → 对方贴图显示。

#### E.1 「mod 能发自定义消息吗」——能，但有硬约束

```csharp
// Core\Multiplayer\Serialization\MessageTypes.cs:13-19
public static void Initialize()
{
    List<Type> list = new List<Type>();
    list.AddRange(INetMessageSubtypes.All);
    list.AddRange(ReflectionHelper.GetSubtypesInMods<INetMessage>());  // ← 主动扫描 mod
    _cache = new NetTypeCache<INetMessage>(list);
}
```

游戏**主动注册** mod 里实现 `INetMessage` 的类型，所以技术上可以自定义消息。

**但是**：`NetTypeCache` 的 ID 是**按类型名字母序排序后顺序编号**的（`NetTypeCache.cs:22-32`）：

```csharp
IEnumerable<ContentSorter<string>.Item> source = ContentSorter<string>.Sort(types, (Type t) => t.Name);
_idToType = source.Select(i => i.type).ToList();
_typeToId[type] = num;   // num = 排序后的下标
```

→ **两端 mod 集合不一致时，整个消息 ID 表会错位**，不只是你的消息失败，是整局网络崩。

这意味着：任何一个定义了 `INetMessage` 的 mod，**必须双方都装**，否则不能联机。
这对「观战 mod」是个致命约束（你没法让只想观战的朋友不装）。

#### E.2 性能代价

| 项 | 数值 |
|---|---|
| 单帧原始大小 | 1920×1080×4 ≈ 8.3 MB |
| 30fps 未压缩 | 250 MB/s —— 完全不可行 |
| JPEG 压缩后（约 80KB/帧） | 2.4 MB/s ≈ 19 Mbps |
| GPU→CPU 回读 | 每帧同步阻塞主线程，观战期间帧率明显下降 |
| 端到端延迟 | 截图 + 编码 + 传输 + 解码 ≥ 300–800 ms |

| 维度 | 评估 |
|---|---|
| 效果 | ★★★☆☆ 真画面，但糊、卡、延迟大 |
| 工作量 | 400–600 行（含自定义消息 + 编码 + 渲染） |
| 风险 | ★★★★☆ 破坏网络兼容性 + 性能崩溃 |

**评价**：能用，但做出来每一项指标都不如 Steam 直播。

---

### 路径 F：原版全屏界面拼装（推荐）

**原理**：游戏里本来就有一堆**全屏界面**，把队友的数据喂进去即可。它们自带背景、动画、翻页、返回键 —— 因为就是原版。

| 想看什么 | 原版界面 | 调用 |
|---|---|---|
| 遗物 + 药水 + 牌库 | `NMultiplayerPlayerExpandedState` | `Create(player)` → `NCapstoneContainer.Instance.Open(screen)` |
| 他的手牌（全屏、翻页、升级预览） | `NInspectCardScreen` | `NGame.Instance.GetInspectCardScreen().Open(cards, 0)` |
| 抽牌堆 / 弃牌堆 | `NCardPileScreen`（`ICapstoneScreen`） | 待接 |

| 维度 | 评估 |
|---|---|
| 效果 | ★★★★★ 100% 原生观感（因为它就是原生） |
| 工作量 | 每个入口 10–30 行 |
| 风险 | ★☆☆☆☆ 只调用公开 API，不改任何状态 |
| 局限 | 是「查看界面」而非「战斗画面」，看不到实时动画 |

**评价**：在「低风险」这个约束下，这是唯一能拿到「完全原生 UI」体验的方案。

## 4. 风险到底来自哪里

把所有风险归因，只有三个源头：

### 4.1 源一：接管了别人节点的生命周期

典型：`_parkedLocalHolders` 暂存手牌 holder。只要中途任何一步抛异常、场景重建、战斗切换，暂存的东西就回不去了。

**规避原则**：只读 + 只画自己的节点。参照物是 `NCard.Create()` —— 它从对象池取新节点，用 `NodePool.Free()` 归还，全程不碰原生 holder。

### 4.2 源二：与其它 mod 抢同一个方法

`NPlayerHand` / `NCombatUi` / `NEnergyCounter` 是热门补丁目标，你装了 74 个 mod，其中至少 5 个在改这片区域。

**规避原则**：补丁目标越少越好。当前只 patch 1 个方法（`NMultiplayerPlayerState._Ready`）；接管方案要 patch 15+ 个。

### 4.3 源三：版本升级时签名变化

活证（本机日志 652–669 行）：工坊 `TeammateSpectate` 在 v0.111.0 上直接初始化失败：

```
HarmonyException: Ambiguous match for HarmonyMethod[
  class=CombatManager, methodname=EndPlayerTurnPhaseOneInternal, args=undefined]
AmbiguousMatchException: Ambiguous match found for
  'CombatManager Task EndPlayerTurnPhaseOneInternal()'
```

游戏给这个方法加了重载，它没指定参数类型，`PatchAll()` 当场抛异常。
**它 patch 了十几个原生方法，这一条就足以让整个 mod 死掉。**

**规避原则**：用 RitsuLib 的 `PatchTarget.Method<T>(name, parameterTypes)` 钉死重载；补丁标记 `IsCritical = false` 让其可静默跳过。

## 5. 推荐路线

### 5.1 立即可用（已完成）

- **B 只读覆盖层**：右上角常驻小窗，鼠标穿透，实时手牌/能量/悬停
- **F 原版界面**：`Shift+右键` → 原版队友详情；`Ctrl+右键` → 原版全屏看牌

### 5.2 想要更强原生感 → A 的分阶段实施

| 阶段 | 内容 | 行数 | 风险 |
|---|---|---|---|
| A1 | displayed player override：顶栏 / 能量 / 星 / 牌堆数字 | ~250 | 中 |
| A2 | 遗物栏 / 药水栏 | ~200 | 中 |
| A3 | 手牌搬运 + 拦交互（必须同时做） | ~550 | **高** |
| A4 | 瞄准箭头复现 | ~300 | 中 |

A1/A2 值得做：视觉提升大、可随时关、失败不影响游戏。
**A3 是分水岭**，做砸了使用者当场不能玩。

### 5.3 不建议做

- **C**：投入产出比最差
- **D**：物理不可行
- **E**：不如 Steam 直播

### 5.4 如果目标就是「直播级体验」

**直接用 Steam 直播**。零 mod 成本、零风险、任何人能看。mod 的价值恰恰在直播做不到的地方：0 延迟、能看清具体数值、能翻他的手牌。
